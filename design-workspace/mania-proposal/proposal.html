MANIA / DESIGN PROPOSAL

Motion, resilience, and implementation

A small transition supports orientation. The task never depends on animation.

1　Ready

Start / Resume is a named button.

2　Opening

120–180 ms press and small shift.

3　Play

Artwork settles. Focus moves to heading.

Reduced motion
Resume → Play

Immediate navigation. No spin or slide.

Accessible by construction

48 px targets, visible keyboard focus, persistent field labels and status announcements. Keep dark text on bright fills.

At 320 px and 200% zoom, stack columns and allow vertical scrolling. Wrap long titles, URLs and 5,000-character reviews. Preserve review line breaks.

Dialogs trap focus, support Escape where safe, and return focus to their trigger. Never communicate state through color alone.

Failure and edge states

Missing artwork: labeled square fallback.
No listening URL: show “No listening link.”
Search fails: retry or enter manually.
Submit fails: keep values and allow retry.
Stale round: refresh state and explain closure.

Long review: wrap fully or offer Read full review. Late joiner: next-game lobby. Completed: final reveal and group entry.

Duplicate pick: preserve search and show the existing rejection. Never clear the chosen metadata on error.

Boundaries for implementation

Reuse current actions, auth and permissions. Keep all hidden review data protected server-side. Recheck role and round on submission.

Additional client work: remembered group, auth return context, transition/focus handling. Cross-visit drafts and automatic polling are optional additions, not current guarantees.

Data check: reviewProgress exists, but verify cross-player totals under RLS. Named pending reviewers or a picker’s display name on Play need a data-contract review. No new public API is proposed.

Review scope Approve the navigation and state hierarchy before implementation. This proposal changes no application code and introduces no game rules.
